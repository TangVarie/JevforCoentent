## 合规歧义（F02）

稿件接口新增 `hard_ambiguous: [[bank, qid], ...]` 和 `needs_review`。硬约束的回答落入题库歧义区时，`passed=false`，进入待复核；不把歧义本身当成确定违规，也不编造改稿指令。普通描述题的歧义不否决整篇。HTTP、MCP、库级生成返回及暗题过滤都保留同一状态。

有答案但证据无效的硬约束歧义仍待复核，不能因为证据缺失反而变成确定违规；真正漏答仍走 `unjudged`。这不声称已经修复所有历史证据标定问题。

**先部署配套 autowriter 修复，再部署本服务。** 新写作台可从旧服务的 `ambiguous ∩ hard_rules` 恢复待复核状态；旧写作台即使收到新版 `passed=false`，仍可能因丢字段而给满分。回滚写作台会重新打开此风险，不能只看本服务版本。

跨库离线验收：检出两个配套 PR 的分支后，在 autowriter 运行：

```bash
python tests/check_judge_contract.py --judge-repo /path/to/JevforCoentent
```

脚本使用真实 ASGI 路由、写作台 HTTP 客户端及最终话术，模型、账本和项目上下文为合成替身，并阻止网络连接。它验证接口语义，不测真实模型准确率。

## 详情诊断（F08）

TikHub 详情的诊断副本只保留脱敏结构、字段类型/长度与白名单状态值，不保留正文、昵称或未知值；先脱敏再截断异常。原正文仍供正常解析/标注处理，不会被诊断脱敏改写。Actions 恢复产物保留 7 天。该变更不清理过去 artifact，也不表示过去已经发生凭据泄露。
